# 工場とランナーの間のメッセージ（ADR 0028 の決定 3）

ランナーと話すのは工場だけです。この文書は、工場とランナーの間を通るメッセージの全部と、ある利用者が別の利用者のランナーに届かないようにする線を書きます。ランナーにできることの範囲は [SCOPE.md](SCOPE.md) にあります。

## 通るメッセージの一覧

### 工場 → ランナー（ランナーが待ち受ける。127.0.0.1:8793）

| 経路 | 認証 | 中身 | 返るもの |
|---|---|---|---|
| `GET /health` | なし | なし | 生きているかと版だけ（道具・端末・機械の名前は返さない） |
| `POST /mcp` の `initialize` / `ping` / `tools/list` | トークン | MCP の決まった形 | サーバーの名前と版、範囲の要約、道具の一覧 |
| `POST /mcp` の `tools/call` | トークン | 道具の名前と引数（SCOPE.md の 18 個だけ。知らない道具・知らない引数は断る） | 道具の結果（下の表） |

これ以外のパス・メソッドは 404 か 405 です。道具の一覧はテスト（`test_tool_list_is_fixed`）で固定し、道具を足すには SCOPE.md・この文書・テストを同じ変更で直してオーナーの承認を通します。サーバーから工場へ押し出す経路（SSE）はありません。

`tools/call` が返す情報は次のものだけです。

| 道具 | 返る情報 |
|---|---|
| `sim_devices` | シミュレーターの UDID・名前・状態・OS の版 |
| `app_build` / `build_status` | ビルドの状態、コミット、bundle id、ビルドのログの末尾（1500 文字） |
| `app_install` / `app_launch` / `app_terminate` / `sim_*` | 成否と UDID・bundle id |
| `screenshot` | シミュレーターの画面の PNG |
| `ui_describe` | シミュレーターの画面の要素（文言・座標） |
| `logs` | 許したアプリのプロセスのログ（直近 10 分まで） |
| `ui_*` / `open_url` / `push` | 成否（打った文字は返さない） |

Mac のファイル・ほかのアプリ・人のシミュレーターの中身・Mac の設定を返す道具はありません。

### ランナー → 工場（ランナーから連絡する。1 分ごと）

| 経路 | 中身 | 工場の返事 |
|---|---|---|
| `GET /api/runners/checkin` | ランナーの id、機械の名前、版、本体と常駐の名前、ポート、OS の版、入っている道具、端末の数、置き場とログの場所、範囲の要約、状態（running / uninstalled） | `{"uninstall": true/false}` だけ |

工場の返事でランナーが動くのは「自分の常駐を外して止まる」の 1 つだけです。返事で道具を呼ばせる・設定を変える経路はありません。

## 穴がないかの確かめ

利用者 A のジョブが、利用者 B の Mac のランナーに、任意のコマンドを実行させたり情報を取ったりできないか。

| 穴になりうる所 | いまの状態 | 線 |
|---|---|---|
| 任意のコマンド | 道具に無い。サブプロセスはシェルを通さない argv の配列 | 閉じている |
| 任意のファイルの読み書き | 道具に無い。返る情報は上の表だけ | 閉じている |
| ビルド | 許したリポジトリの、マージ済みのコミットのコードが Mac の上で動く（「任意のコマンド」に近い唯一の経路）。許すリポジトリは Mac 側の設定で、工場からは広げられない | 歯止めはマージ済みに限ること |
| 人のシミュレーターの画面 | `screenshot` と `ui_describe` は、持ち主が私用で起動しているシミュレーターも読める | 開いている（絞らない判断。顧客向けの説明に書く） |
| 画面の任意の場所の操作 | `ui_tap` などの座標はシミュレーターの画面の中だけ（idb がシミュレーターに送る。Mac の画面には届かない） | 閉じている |
| ネットワークの外からランナーに繋ぐ | 待ち受けは 127.0.0.1 だけ | 閉じている |
| **トークンを持ったジョブが、ジョブの外でも使う** | Gen1 の設計（`macrunner_client.mcp_config()`）は、QA のワーカーにトークンをそのまま渡す。ワーカーはジョブの間は任意のコードを動かせるので、トークンを持ち出せる | **開いている。one_orchestrator で閉じる（下の決めたいこと 1）** |
| **工場が別の利用者のジョブに、そのランナーを渡す** | Gen1 はランナー 1 台・製品 1 つなので起きない。ランナーと製品（利用者）の結びつきは記録していない | **開いている。2 台目・2 社目の前に閉じる（決めたいこと 2）** |
| 偽のランナーの登録・画面からの外し | 操業コンソールはログインなし。`CONSOLE_BIND=0.0.0.0` だと同じ LAN から届く | 開いている。被害はランナーが止まる・一覧が汚れるだけ（決めたいこと 3） |

## 決めたいこと（オーナーの承認）

1. **ワーカーにトークンを渡さない**: dispatcher がジョブごとに、ランナーへの中継（MCP の口）を立てる。ワーカーはそこにだけ繋ぎ、本物のトークンは dispatcher の外に出さない。中継はジョブの間だけ開き、そのジョブに許した道具だけを通す（例: QA のジョブは見る・操作する道具だけで、`sim_erase` は通さない）。呼んだ道具は工場の events にも残す
2. **ランナーを利用者（製品）に結びつける**: 登録のときにランナーの持ち主の製品を決め、中継は「ジョブの製品＝ランナーの持ち主」のときだけ開く。ランナー側も、許したアプリ（`MAC_RUNNER_APPS`）以外はビルドも操作もしない（今の守り）ので、二重になる
3. **コンソールの操作の認証**: 商用化で操業コンソールにログインが入るときに、ランナーの連絡にもランナーごとの鍵を足す。それまでは CONSOLE_BIND を 127.0.0.1 にしておけば LAN からは届かない

4. **安全の判定は Mac 側に置く**: アプリの許可・URL の許可・ビルドしてよいリポジトリは Mac の設定で、工場は頼むだけ。工場がそれを広げるメッセージは作らない
5. **登録済みのランナーの一覧は表示だけに使う**: 一覧（ランナーからの連絡）を、工場が繋ぎに行く先の根拠にしない（偽の登録で工場を別の宛先に向けられないように）
6. **別の機械のランナーは、ランナーから仕事を取りに行く形にする**: 顧客の Mac に待ち受けを開けない（今の連絡と同じ向き）。ネットワークの設定でハマらない

1 は one_orchestrator（QA のワーカーに Mac ランナーを渡す）の作り方そのものなので、その PR で入れる。4・5 は今の作りのまま守る（この文書で約束にする）。2・3・6 は 2 台目のランナーか 2 社目の工場の前に入れる。

## 案: ペアリング（オーナー 2026-11-05「Bluetooth のペアリングのように、設定のときに両方で承認」。承認待ち）

決めたいこと 2・3 を、ランナーと工場のペアリングで閉じる。

1. Mac で `macrunner.sh install` を流すと、ランナーが工場に接続の依頼を送り、ターミナルに 6 桁の番号を出す（「工場の画面に 482 913 と出ていれば y」）
2. 操業コンソールの「登録済みのランナー」に、同じ番号の接続の依頼が出る。人が番号を見比べて「許可」を押し、どの製品のランナーかを選ぶ
3. 両方で OK がそろうと、そのランナー専用の鍵ができて両側に保存される。以後の道具の呼び出しと 1 分ごとの連絡は、すべてこの鍵で確かめる

決まりごと:

- 依頼は 10 分で切れる。切れたらやり直す
- 番号は両側の乱数から作る（片方だけで決められない）
- 許可されるまで、ランナーはどの道具も受けず、工場もそのランナーを使わない
- 外すと鍵を捨てる。外した Mac・持ち出された Mac は、ペアリングし直すまで工場と話せない
- 工場側の鍵は制御プレーンの DB に置き、dispatcher だけが読む（ジョブのワーカーには渡さない。決めたいこと 1）
- `.env` へのトークンの写しと、そのための工場の上げ直しは要らなくなる
- ランナーは macOS 標準の Python の標準ライブラリだけで動かすので、公開鍵ではなくペアリングで共有する鍵にする

これだけでは閉じないもの:

- 操業コンソールのログイン: 同じ LAN の人が工場側の「許可」を押せる（Mac 側の y がないと完了しないので、他人の Mac は繋げない）。利用者を増やす前に要る
- 通信の暗号化: いまは同じ Mac の中なので要らない。別の機械のランナーを使う段階で TLS が要る

今入っている 1 台は、切り替えのときに 1 回ペアリングし直す。
