# 工場とランナーの間のメッセージ（ADR 0028 の決定 3）

ランナーと話すのは工場だけです。この文書は、工場とランナーの間を通るメッセージの全部と、ある利用者が別の利用者のランナーに届かないようにする線を書きます。ランナーにできることの範囲は [SCOPE.md](SCOPE.md) にあります。

## 通るメッセージの一覧

ランナーは待ち受けません。工場のランナーの窓口（`dispatcher/runner_gate.py`、compose の `runner-gate`）へ、ランナーから TLS で取りに行きます（ADR 0033）。

### ランナー → 窓口（TLS :8794。工場の自分用の証明書。ランナーはペアリングのときに指紋を覚え、以後はそれ以外と話さない）

| 経路 | 認証 | 中身 | 窓口の返事 |
|---|---|---|---|
| `POST /pair/start` | なし | ランナーの乱数のハッシュ、自己紹介（下） | pair_id と窓口の乱数 |
| `POST /pair/reveal` | 乱数がハッシュに合うこと | ランナーの乱数 | なし（両側で 6 桁の番号を計算でき、窓口はコンソールに出す） |
| `POST /pair/confirm` | 同上 | Mac で y を押した | なし |
| `POST /pair/wait` | 同上 | 許可を待つ（25 秒の長いポーリング） | 待ち、拒否・切れた、または両方そろったときに 1 回だけランナーの id と鍵 |
| `POST /poll` | 鍵の署名 | 自己紹介（5 分に 1 回まで） | `{calls: [{call_id, tool, arguments}]}` か `{uninstall: true}` |
| `POST /result` | 鍵の署名 | call_id と道具の結果（下の表） | なし |
| `POST /bye` | 鍵の署名 | Mac 側で外した | なし（窓口が鍵を捨てる） |

自己紹介は、機械の名前、版、本体と常駐の名前、OS・Xcode・Flutter の版、入っている道具、端末の数、置き場とログの場所、範囲の要約、受けられる数です。署名は `HMAC-SHA256(鍵, 時刻 \n パス \n 本文)` で、時刻のずれは 5 分まで許します。これ以外のパス・メソッドは 404 です。

### 窓口 → ランナー（`/poll` の返事だけ）

窓口がランナーに渡せるのは、道具の呼び出し（SCOPE.md の 18 個。一覧はランナーの側で固定し、知らない道具・知らない引数はランナーが断る）と、外す依頼の 2 つだけです。外す依頼でランナーが動くのは「鍵を捨てて自分の常駐を外して止まる」だけです。返事で設定を変える・道具を足す経路はありません。道具の一覧はテスト（`test_tool_list_is_fixed`）で固定し、道具を足すには SCOPE.md・この文書・テストを同じ変更で直してオーナーの承認を通します。

`/result` で返る情報は次のものだけです。

| 道具 | 返る情報 |
|---|---|
| `sim_devices` | シミュレーターの UDID・名前・状態・OS の版 |
| `app_build` / `build_status` | ビルドの状態、コミット、bundle id、ビルドのログの末尾（1500 文字） |
| `app_install` / `app_launch` / `app_terminate` / `sim_*` | 成否と UDID・bundle id |
| `screenshot` | シミュレーターの画面の PNG |
| `ui_describe` | シミュレーターの画面の要素（文言・座標） |
| `logs` | 許したアプリのプロセスのログ（直近 10 分まで） |
| `ui_*` / `open_url` / `push` | 成否（打った文字は返さない） |

Mac のファイル・ほかのアプリ・人のシミュレーターの中身・Mac の設定を返す道具はありません。

### 工場の中 → 窓口（平文 :8795。compose の網の中だけで公開しない）

| 経路 | 認証 | 中身 | 返るもの |
|---|---|---|---|
| `POST /internal/call` | 中向けの合言葉 | ランナー（id か `any`）、道具、引数、待つ秒 | 結果。`any` は窓口に来ているランナーのうち、預けている呼び出しの少ないものに渡す |
| `GET /internal/runners` | 同上 | なし | ペアリング済みのランナーと、窓口に来ているか・預けている数 |

合言葉は窓口の置き場（`runnergate` ボリューム）のファイルで、dispatcher だけが読み取り専用でマウントします。ジョブのワーカーにはマウントしません。

## 穴がないかの確かめ

利用者 A のジョブが、利用者 B の Mac のランナーに、任意のコマンドを実行させたり情報を取ったりできないか。

| 穴になりうる所 | いまの状態 | 線 |
|---|---|---|
| 任意のコマンド | 道具に無い。サブプロセスはシェルを通さない argv の配列 | 閉じている |
| 任意のファイルの読み書き | 道具に無い。返る情報は上の表だけ | 閉じている |
| ビルド | 許したリポジトリの、マージ済みのコミットのコードが Mac の上で動く（「任意のコマンド」に近い唯一の経路）。許すリポジトリは Mac 側の設定で、工場からは広げられない | 歯止めはマージ済みに限ること |
| 人のシミュレーターの画面 | `screenshot` と `ui_describe` は、持ち主が私用で起動しているシミュレーターも読める | 開いている（絞らない判断。顧客向けの説明に書く） |
| 画面の任意の場所の操作 | `ui_tap` などの座標はシミュレーターの画面の中だけ（idb がシミュレーターに送る。Mac の画面には届かない） | 閉じている |
| ネットワークの外からランナーに繋ぐ | ランナーは待ち受けない（取りに行くだけ） | 閉じている |
| 鍵を持ったジョブが、ジョブの外でも使う | 鍵は窓口の置き場と Mac にだけあり、ワーカーには渡さない。中向けの合言葉も dispatcher だけが読む。ワーカーに渡すのは one_orchestrator のジョブごとの中継だけ | 閉じている（中継で通す道具を絞るのは one_orchestrator。決めたいこと 1） |
| 別の工場（別の事業主）のジョブが、そのランナーを使う | ランナーはペアリングした 1 つの工場の窓口とだけ話す（証明書の指紋と鍵）。1 つの工場は 1 つの事業主のもので、社内の人が共有する（ADR 0033） | 閉じている |
| 偽のランナーの登録・画面からの外し | 登録は両方の承認（コンソールの「許可」と Mac の y）が要る。操業コンソールはログインなしなので、`CONSOLE_BIND=0.0.0.0` だと同じ LAN の人が「許可」「外す」を押せる | 半分。他人の Mac は繋げない（Mac の y が要る）。コンソールのログインは Gen2 以降（決めたいこと 3） |

## 決めたいこと（オーナーの承認）

1. **ワーカーに鍵を渡さない**: dispatcher がジョブごとに、ランナーへの中継（MCP の口）を立てる。ワーカーはそこにだけ繋ぎ、ランナーの鍵と窓口の合言葉は工場の外に出さない。中継はジョブの間だけ開き、そのジョブに許した道具だけを通す（例: QA のジョブは見る・操作する道具だけで、`sim_erase` は通さない）。呼んだ道具は工場の events にも残す
2. **ランナーを利用者に結びつける**: ペアリングで、ランナーを 1 つの工場（1 つの事業主）に結ぶ。工場は事業主の社内で共有するので、製品ごとには分けない（ADR 0033）。ランナー側も、許したアプリ（`MAC_RUNNER_APPS`）以外はビルドも操作もしない
3. **コンソールの操作の認証**: ランナーの連絡はランナーごとの鍵で確かめる（ADR 0033 の順番 2 で入った）。操業コンソールのログインは Gen2 以降。それまでは CONSOLE_BIND を 127.0.0.1 にしておけば LAN からは届かない

4. **安全の判定は Mac 側に置く**: アプリの許可・URL の許可・ビルドしてよいリポジトリは Mac の設定で、工場は頼むだけ。工場がそれを広げるメッセージは作らない
5. **登録済みのランナーの一覧は表示だけに使う**: 一覧（ランナーからの連絡）を、工場が繋ぎに行く先の根拠にしない（偽の登録で工場を別の宛先に向けられないように）
6. **ランナーから仕事を取りに行く形にする**: Mac に待ち受けを開けない。ネットワークの設定でハマらない（ADR 0033 の順番 2 で入った）

1 は one_orchestrator（QA のワーカーに Mac ランナーを渡す）の作り方そのものなので、その PR で入れる。4・5 は今の作りのまま守る（この文書で約束にする）。2・3（ランナーの側）・6 は ADR 0033 の順番 2 で入った。

## ペアリング（オーナー 2026-11-05「Bluetooth のペアリングのように、設定のときに両方で承認」。ADR 0033 で承認（2026-11-05）、順番 2 で入った）

決めたいこと 2・3 を、ランナーと工場のペアリングで閉じる。

1. Mac で `macrunner.sh install` を流すと、ランナーが工場に接続の依頼を送り、ターミナルに 6 桁の番号を出す（「工場の画面に 482 913 と出ていれば y」）
2. 操業コンソールの「登録済みのランナー」に、同じ番号の接続の依頼が出る。人が番号を見比べて「許可」を押す
3. 両方で OK がそろうと、そのランナー専用の鍵ができて両側に保存される。以後の取りに行く・結果を返す・外すは、すべてこの鍵で確かめる

決まりごと:

- 依頼は 10 分で切れる。切れたらやり直す
- 番号は両側の乱数と窓口の証明書の指紋から作る。ランナーは先に乱数のハッシュだけを出し、窓口の乱数を受け取ってから乱数を明かすので、間に入った者も片方だけでも番号を合わせられない
- 許可されるまで、ランナーはどの道具も受けず、工場もそのランナーを使わない
- 外すと鍵を捨てる。外した Mac・持ち出された Mac は、ペアリングし直すまで工場と話せない
- 工場側の鍵は窓口の置き場のボリューム（`runnergate`、0600）に置き、窓口だけが読む。events には書かない（ジョブのワーカーには渡さない。決めたいこと 1）
- `.env` へのトークンの写しと、そのための工場の上げ直しは要らなくなる
- ランナーは macOS 標準の Python の標準ライブラリだけで動かすので、公開鍵ではなくペアリングで共有する鍵にする

これだけでは閉じないもの:

- 操業コンソールのログイン: 同じ LAN の人が工場側の「許可」を押せる（Mac 側の y がないと完了しないので、他人の Mac は繋げない）。利用者を増やす前に要る

今入っている 1 台は、切り替えのときに 1 回ペアリングし直す。
