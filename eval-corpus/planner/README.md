# プランナーの評価セット（ADR 0036 の 4b）

`cases.yaml` は rally の実チケットの写しと、人が付けた正解（`expected`: 切るべきか・触る層・ターンの帯・経路）。`actual` は実際の PR の実績（ファイル数・層・ターン）で、正解を付けた材料。`confirmed: false` の正解は建設者がオーナーの代理で付けた案で、オーナーの確認待ち。

- 回し方は `core-gates/plan_bench.py`（`orchestrator/README.md` の「固定の評価セットのベンチ」）
- 正解は規則の当てはめではなく「1 件のままでよかったか」で付ける。規則と食い違う件（例: 契約と backend のチケットで admin-web は生成した型の追従だけ）は `note` に書き、規則を見直す材料にする
- 本文が長いチケットは 12000 文字で切ってある
