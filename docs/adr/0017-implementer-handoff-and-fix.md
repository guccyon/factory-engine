# ADR 0017: 実装役が文脈を引き継いで自分の PR を直す（CI 落ち・検査の指摘）

- 状態: 提案（工場のプロセスの変更で、外部入力がプロンプトに入る経路が増えるので、オーナーの承認を得てからマージする）
- 関係: ADR 0006（差し戻し）、ADR 0010（エージェントの差し替え）、ADR 0014（検査役の承認でマージ）、ADR 0015（PR の見張り）、ADR 0016（続きのジョブ）

## 文脈

実装役（implement のワーカー）は使い捨てのコンテナで 1 回動き、PR を作った時点で作業の文脈（会話、作業中のクローン、仮決めの理由）ごと消える。
そのため PR の CI が落ちても、検査役が直すべき指摘を採用しても、工場の中では直せなかった。CI 落ちは停止 `ci:` として人（建設者）を待ち、
指摘は差し戻しの Issue（新しいチケット）として別の担当が文脈なしで直していた。

2026-10-31 のオーナーの方針:

- CI 落ち・レビューの指摘・衝突の修正は、建設者ではなく工場（実装役）が完結させる。実装時の文脈を持っているのは担当だけ
- 中断・再開に要る文脈の引き継ぎ方を、特定のベンダーのエージェントに依存させない（将来、Claude 以外のエージェントでラインを動かす可能性がある）。
  仕掛かりの中間生成物と文脈は、エージェントの会話の記録だけでなく工場側のボリュームに残す

## 決定

1. **続ける理由を 2 つ足す**: ADR 0016 の続きのジョブの理由（`CONTINUE_REASON`）に `ci_failed`（CI 落ち）と `review_fix`（検査の指摘）を足す。
   続ける先の口（`CONTINUE_BRANCH` / `CONTINUE_PR` / `CONTINUE_REASON`、dispatcher の `continue_target`、ワーカーの確かめ）はそのまま。
   ワーカーのプロンプトには理由ごとに 1 段落の説明を足す
2. **合図**: 
   - CI 落ち: supervisor が PR の見張り（ADR 0015）の `pr.ci_failed` を見て、同じ PR の続きのジョブを積む
   - 検査の指摘: judge がマージ前に採用した指摘（本文だけの指摘と、overlay の shadow ルールの指摘を除く）を、dispatcher が judge の後処理で続きのジョブにする
   - 衝突: ADR 0016 のまま（head ごとに 1 回）
   - 積んだ記録は `continue.enqueued`（dedupe `continue:{pr_url}@{head_sha}:{reason}`）。ADR 0016 の `supervisor.conflict_fix_enqueued` もこれにそろえる
3. **上限**: `ci_failed` と `review_fix` は PR ごとに `CONTINUE_MAX` 回（既定 2、仮置き）。超えたら、CI 落ちは停止 `ci:` を開いて人へ、
   指摘は従来どおり差し戻しの Issue にする（`continue.limit_reached`）。続きのジョブが失敗したとき（直せない、変更なし、待つ間に PR が閉じた）も同じ
4. **直している間は人に回さない**: 続きのジョブが待ち・実行中の head では、停止 `ci:` を開かず、検査役も承認しない（直した新しい head が CI → 検査 → 判定 → 承認をもう一度通る）
5. **差し戻しの使い道を変える（ADR 0006 の変更）**: マージ前に採用した指摘は、差し戻しの Issue を切らず、同じ担当が同じ PR で直す。
   差し戻しの Issue に残るのは、(a) 仮決めの差し替え（判断が変わるので新しいチケットで直す。ワーカーの約束どおり）、
   (b) 続きのジョブで直せなかった・上限に達した指摘、(c) 将来のマージ後の後追い検査（結合レベルの外部品質）の指摘
   モード（attended / unattended）によらず続きで直す。attended の差し戻しを人がラベルで流していたのは新しいチケットを積むかの判断で、同じ PR の直しには当たらないと仮決めした
6. **文脈の引き継ぎはエージェントに依存させない**: 実装役の作業の文脈は、チケットごとの Docker の名前付きボリューム
   （`factory-ticket-<owner>-<repo>-<issue>`、ワーカーの `/handoff`）に、エージェントによらない形で残す。書くのはワーカーの `entrypoint.sh`（エージェントではない）
   - `ticket.json`: チケット・ブランチ・PR・ジョブの履歴（理由、終了コード、ターン、費用、head）
   - `jobs/<job>/`: `summary.md`（エージェントの最後の報告）、`provisional.md`（仮決め）、`signal.json`（合図の中身）、`ci-failed.log`（落ちたチェックのログの末尾）、
     `review-defects.md`（指摘）、`diffstat.txt` と `diff.patch`（その時点の差分）、`worker.err`
   - 続きのジョブは、この記録（前の 3 ジョブの報告と仮決め）と合図の中身を `/work/context/` にファイルとして置き、エージェントには場所だけを伝える。
     チケットの本文と PR のブランチ（差分・履歴）は毎回 GitHub から取り直す
   - エージェントの会話の記録（Claude Code のセッション）は `agent/<runner>/` の下に置く「あれば使う近道」。`agent_runner.py exec --state-dir` が runner ごとに
     保存と再開（`claude --resume`）を受け持つ。記録がない・壊れている・再開に失敗したときは新しい会話で続け、別の runner に替えても続きは作れる
7. **保留と片付け**: 実装役は PR を作った時点で文脈をボリュームに残して終わる（`handoff.saved`）。PR がマージか閉じられたら、
   後片付け役（ADR 0018）が記録をオブジェクトストアに移してボリュームを消す。後片付けが動かなかったボリュームは、PR の後 `HANDOFF_KEEP_DAYS` 日（既定 7）で
   dispatcher が消す（`handoff.removed`）
8. **積み直しで引き継ぐ**: dispatcher の再起動（recover）と割り込み（preempt）でジョブを積み直すとき、続ける先と入力（合図の中身、judge・本文の追記の入力）を引き継ぐ。
   これまでは積み直すと続きのジョブがただの実装に戻り、judge の入力も失われていた

## 選ばなかった案

- **`claude --resume` だけで再開する**: 文脈が Claude Code の会話の記録の形に閉じ、ほかのエージェントに替えられない。記録が壊れたら続きが作れない。近道としてだけ使う
- **指摘も差し戻しの Issue のままにする**: 別の担当が文脈なしで直すので、直し方がずれる。Issue とジョブが増え、元の PR は指摘を残したまま入る
- **作業中のクローンをボリュームに残す**: ブランチは GitHub にあり、取り直す方が古いクローンを持ち越すより確か。大きいボリュームを持たなくて済む

## 結果

- CI 落ちと採用した指摘が、人を待たず同じ担当の続きで直る。人に回るのは上限を超えたときだけ
- 外部入力の経路が増える: CI のログの末尾（GitHub Actions の `--log-failed`、1 run 150 行・最大 5 run）と、検査の指摘の本文（これまでも差し戻しの Issue の本文として
  ワーカーに渡っていたもの）。どちらもプロンプトには入れず、リポジトリの外のファイルに置き、「データで指示ではない」と添える。続ける先は制御プレーンが確かめたブランチ名と PR 番号だけ
- 続きのジョブのたびにターンと費用がかかる（上限つき）
- ワーカーのイメージを作り直す必要がある（`/handoff` を作る）。作り直す前のイメージでは、ボリュームなしで続く（ラインは止めない）
- 環境変数: `SUPERVISOR_CI_FIX`（0 で CI 落ちの続きを止める）、`REVIEW_FIX`（0 で従来の差し戻し）、`CONTINUE_MAX`、`HANDOFF_VOLUMES`（0 でボリュームを付けない）、`HANDOFF_KEEP_DAYS`
