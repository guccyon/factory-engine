# ADR 0018: ラインの後片付け役

- 状態: 承認（役割の置き方は 2026-10-31 オーナーが選んだ。中身の実装はこの ADR を入れる PR のレビューで確かめる）
- 関係: ADR 0009（チケット）、ADR 0010（エージェントの差し替え）、ADR 0017（実装役の引き継ぎのボリューム）、ケイパビリティ台帳 A13・C8

## 文脈

ADR 0017 で、実装役の作業の文脈（報告、仮決め、合図、差分）をチケットごとのボリュームに残すようになった。チケットが終わると、
ボリュームに中間生成物が残り、保留した判断（人に回した判断、確信度の低い仮決め）や範囲外にしたこと、次のタスクに効く事実が散らばったままになる。
何を残し、何を捨て、何を次に渡すかを裁く担当がいなかった。

指示役（supervisor）に持たせると、ラインに流す・合図を拾うに加えて中身の判断まで持つことになり、責務が大きすぎる。
実装役の最後に足すと、マージ後・差し戻し後の片付けができず、実装役の文脈が長くなる。ロールを作りすぎるのも避けたい（2026-10-31 オーナー）。

## 決定

1. **後片付け役を置く**: ラインの最後の工程。指示役はチケットの PR がマージか閉じられたら、そのチケットにボリュームが残っていれば、後片付けのジョブ
   （`kind=cleanup`）を PR ごとに 1 回積む（`supervisor.cleanup_enqueued`）。同じチケットのジョブが動いていれば次の周期で積み直す
2. **永続化と破棄は機械**（dispatcher、LLM を使わない）:
   - 永続化: ボリュームの引き継ぎの記録（`ticket.json`・`jobs/`）を tar.gz でオブジェクトストアの `tickets/<repo>/<issue>/handoff-job-<job>.tar.gz` に移す（`handoff.archived`）
   - 破棄: エージェントの会話の記録（`agent/`）は移さない。移せたらボリュームを消す（`handoff.removed`、why=cleanup）。移せなかったらボリュームは消さず、ADR 0017 の期限の片付けに任せる
3. **申し送りと再起票は案だけ**（工程 `cleanup`、ツールなし、tier-small）: ボリュームの実装役の報告（「補足」「知見」「仮決め」）と、制御プレーンの記録
   （PR の結末、judge が人に回した判断、差し戻し、続きのジョブの回数）から、
   - 申し送り: 同じリポジトリの次のタスクに効く事実（最大 5 件、1 件 1 文）
   - 再起票: 保留したまま閉じた判断と、範囲外にしたことのうち抜け落ちそうなもの（最大 5 件、題・理由・本文の案。差し戻しの Issue があるものは除く）
   を出す。案は `CleanupReport` に残し、案があればチケットの Issue にコメントする。**起票はしない**。採るかは建設者が決める。案の採否が溜まったら、自動で起票する範囲を決め直す
4. 止め方: `SUPERVISOR_CLEANUP=0`

## 選ばなかった案

- **期限で消すだけ（ADR 0017 のまま）**: 申し送りと保留判断の再起票が落ちる
- **実装役の最後に足す**: 新しい役割は要らないが、マージ後・差し戻し後の片付けができない
- **申し送りを自動で次のチケットに書き込む・再起票を自動で起票する**: 案の質がまだ分からない。最初は案だけにして、採否を見てから広げる

## 結果

- チケットの文脈がオブジェクトストアに残り、ボリュームは終わったチケットの分から消える。ラインのセッションの詳細ログの保持（C8）の置き場所の足がかりになる（会話の記録はまだ移さない）
- チケットごとに 1 回、小さいモデルの呼び出しが増える
- 外部入力の経路: 後片付けのプロンプトに入るのは、実装役の報告と仮決め（エージェントの出力）と、制御プレーンの記録だけ。Issue と PR の本文は渡さない。案は「データ」として引用してコメントに書く
- ワーカーのイメージを作り直す必要がある（`cleanup.sh`）
