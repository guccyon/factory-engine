# ADR 0018: ラインの後片付け（小さく、機械だけ、ラインとは非同期）

- 状態: 承認（2026-10-31 オーナー。後片付けの役割を置く。最初は小さく機械的な片付けだけ）
- 関係: ADR 0013（Learn ループ）、ADR 0017（実装役の引き継ぎのボリューム）、ケイパビリティ台帳 A13・C8

## 文脈

ADR 0017 で、実装役の作業の文脈（報告、仮決め、合図、差分、エージェントの会話の記録）をチケットごとのボリュームに残すようになった。
チケットが終わったあと、これを何も考えずに消すと、Learn ループ（ADR 0013）と工場の健康指標の材料が失われる。
一方で、指示役に後片付けを持たせると責務が大きすぎ、実装役の最後に足すとマージ後の片付けができない。

2026-10-31 オーナー:

- 後片付けの役割は置くが、最初は小さく機械的な片付けだけでよい
- セッションの生データをそのまま渡すと学習側の精査が大変なので、残すにしても一定のクレンジングは要る。ただし、Learn ループの設計が固まり、学習の入力に何が要るかが分かった時点で、片付けの流れを見直す。健康指標の可視化側からの要求も加味する
- 片付けはラインの完了をきっかけにするが、ラインの作業とは非同期に扱い、成果物には含めない。出荷するかは人が判断し、出荷できないと判断したときの手戻りを小さく保つため、ラインのオーバーヘッドを増やさない

## 決定

1. **ラインの外で動く**: 後片付けは dispatcher の別の糸（`tidy_loop`、既定 5 分ごと）で動く。ジョブとして積まず、ジョブの枠も使わない。PR にも Issue にも何も足さない
2. **きっかけ**: 工場の PR がマージか閉じられ（`pr.merged` / `pr.closed_unmerged`）、そのチケットに引き継ぎのボリュームが残っていて、同じチケットのジョブが動いていないこと
3. **永続化**: ボリュームの中身を、選り分けずにそのまま tar.gz でオブジェクトストアの `tickets/<repo>/<issue>/handoff-<日時>.tar.gz` に移す（`handoff.archived`）。
   エージェントの会話の記録（`agent/`）も含める。後で要る入力が分かってから選り分けられるよう、今は落とさない
4. **破棄**: 移せたらボリュームを消す（`handoff.removed`、why=tidy）。移せなければ消さずに次の回で移し直す。移せないまま PR の後 `HANDOFF_KEEP_DAYS` 日（既定 7）たったら消す（why=keep_days）
5. **LLM は使わない**。申し送り、保留した判断の再起票、データのクレンジングは、Learn ループの入力データと健康指標の要求が見えた時点で、この ADR を改めて決め直す

## 選ばなかった案

- **後片付けをラインの最後のジョブにする**（指示役が積み、エージェントが申し送りと再起票の案を出す）: ラインの完走が延び、出荷しない判断のときの手戻りが大きくなる。案の質を測る土台もまだない（2026-10-31 に一度実装し、オーナーの方針で取り下げた）
- **期限で消すだけ**: Learn ループと健康指標の材料が失われる
- **今からクレンジングして残す**: 何を残すべきかは学習側の入力が決まってからでないと決められない

## 結果

- ラインの完走時間と成果物は変わらない
- チケットの文脈がオブジェクトストアに残る。Learn ループ（P3）と健康指標（台帳 C8）の入力の候補になる。会話の記録を含むので大きくなり得る。保持期間と選り分けは見直しのときに決める
- 見直しのきっかけ: P3 で学習の入力データの形が決まったとき、健康指標で使うセッションログの項目が決まったとき
