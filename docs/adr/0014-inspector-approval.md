# ADR 0014: 検査役がマージを承認する

- 状態: 承認（2026-10-31 オーナー。停止調査スレッド）
- 関係: ADR 0004（supervisor は判断しない）、ADR 0006（judge と判断の記録）、ADR 0005（番人）、製品の manifest（autonomy）

## 文脈

2026-10-30 夜、工場の PR が CI 緑・検査・judge の採用まで済んだのに、約 5 時間 40 分ラインが止まった。製品の manifest の `phase_grants.P0.merge` が human_approve で、工場は「表は auto」と記録するだけでマージせず、マージは会話スレッド（builder）の役目だった。その builder のセッションが夜間に切れた。

オーナーの方針（2026-10-31）:

- 自動でよい基準のものは自動でマージする。マージ役は置かない
- マージ基準は「工場建設用」と「工場が作るプロダクト用」の 2 本を持ち、後者は rally の実装を通して大胆に自動へ育てる
- 人がやる承認を、工場の新しい役割 **検査役** に委任する。基準を満たすものは自動で承認し、判断が難しいものだけ人に回す。これで「基本は自動承認、基準を満たせないものだけ人へ」を構造として作る
- 検査は内部品質（PR の承認に要るコードの品質）と外部品質（アプリを実際に動かして見る品質）で、判断の文脈も、やり方も、進化の仕方も違う。知見は分けて溜めるが、まずは 1 つの検査役が兼務する
- 外部品質には、ラインの途中で PR のマージ前に行う検査と、マージはするが後追いで行う結合レベルの検査の 2 種類が要る（体系はこれから）

これまでの順番は「CI 緑 → マージの判定（表が auto なら即マージ）→ 検査 → judge → 差し戻し」で、検査と judge はマージの後追いだった。承認を検査役に委任するには、マージを検査役の後に置く必要がある。

## 決定

1. **マージの条件を「CI 緑 ＋ 表が auto ＋ 検査役の承認」にする**。supervisor は表が auto の PR でも即マージせず、検査役の承認（`supervisor.inspector_approved`）が出た周期にマージする。判定（`supervisor.merge_decided`）は従来どおり先に記録し、検査ジョブを積む
2. **検査役は、いまは検査（inspect）と judge の組み合わせ**。その head で検査と judge が終わり、judge が人に回した判断（escalate）がなければ承認する。人に回した判断があれば、人が停止 `judge:` を閉じるまで待つ（人が PR を閉じれば従来どおり記録して終わる）。検査で仮決めも指摘もなければ judge は積まれないので、その時点で承認する
3. **採用された指摘はマージを止めない**。差し戻しの Issue で直す（ADR 0006 の 9、ラインを止めない D7）。検査役の承認は「このまま main に入れてよい」であって「指摘がない」ではない
4. **内部品質と外部品質は分けて育てる**。本 ADR で動くのは内部品質（コードと PR 本文の検査、仮決めの判定）だけ。外部品質（アプリの実行環境を用意して動かす試験、探索的テスト）は別の検査として足す。マージ前に行うものは検査役の承認の条件に加わり、後追いで行う結合レベルのものはマージ後に走って差し戻しを起票する。判断の基準・観点・実績は内部と外部で別に記録する（内部品質の指標の整理は別スレッドで進行中）
5. **検査がなければ CI 緑で承認とみなす**（`SUPERVISOR_INSPECT=0`、judge がなければ検査済みで承認）。検査役を外した工場でも止まらない

## 選ばなかった案

- **マージ役（会話スレッド）を置き続ける**: 夜間にセッションが切れると止まる。オーナーがマージ役は不要とした
- **従来どおり CI 緑で即マージし、検査は後追いのまま**: 「承認を委任する」構造にならず、検査役が人に回したいものも先に main に入る
- **検査の指摘があればマージを止める**: ラインが止まる（D7）。指摘は差し戻しで直し、品質の差は統計で見る
- **夜間だけ自動マージ**: モードと権限が別の軸で、Engine の作りを変える割に得るものが小さい

## 結果

- 工場の PR は、CI 緑から検査・judge を経て数分でマージされる。builder のセッションがなくてもラインは回る
- 人に回した判断がある PR だけが人を待つ。待っている間は停止 `judge:` と PR のラベル `factory:needs-judgment` で見える
- 製品の manifest の `phase_grants` の merge を auto にしないと工場はマージしない（rally #257）。表の値（matrix・always_human_approve）はそのまま効く
