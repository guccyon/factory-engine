# ADR 0022: 週 1 回の設計の診断（ドメインモデリングの読み込み）

- 状態: 承認（2026-10-31 オーナー。決定カードで「週 1 回、工場の工程に足す」）
- 関係: ADR 0019（内部品質の定期診断）、ADR 0008（建設状況の日次レポート）、ADR 0010（エージェントの呼び出し）、`definitions/design_review.yaml`

## 文脈

ADR 0019 で、製品のコードの作りを数値（複雑さ・長さ・重複・テストの数など）で毎日測るようになった。
2026-10-31 オーナー: 「アプリ側のドメインモデリングなどの品質を見たい。工場のダッシュボードから見られるのが良い」。

数値に出ないものがある。用語集とコードの名前のずれ、コンテキストどうしの依存の輪、不変条件が集約の外から破れる道、業務の失敗が 1 つの型に集まって変更が集中していること、などで、コードと specs/ を読み比べないと分からない。
建設者が手で 1 回読んで報告を作った（rally の第 1 回）。オーナーはこれを週 1 回、工場の工程にすることを選んだ。

## 決定

1. **観点・重さ・出力の上限を `definitions/design_review.yaml` に置く**。観点は 7 つ（用語、コンテキストの境界、集約と不変条件、層、失敗の表し方、画面のアプリ、説明と実装のずれ）。観点を足す・外すのはオーナーの承認（ADR 0019 と同じく、基準の変更は人が承認）
2. **supervisor が週 1 回、製品ごとにジョブ（kind=design_review）を積む**。既定は土曜 2 時（JST）を過ぎたら、その ISO 週に 1 回（`supervisor.design_review:<repo>:<週>` で重複を防ぐ）。製品は `QUALITY_REPOS`、なければ `FACTORY_REPOS`。ジョブは製品の固定 Issue（ラベル `factory:design-review`、なければ作る）に積む。前回の所見の題と重さを入力に渡し、直ったか残っているかを見させる
3. **ワーカーは読むだけ**。`design_review.sh` が製品の既定ブランチを clone し、`core-gates/design_review.py` が agent_runner の工程 `design_review`（tier-judge）でエージェントにコードと specs/・docs/adr/ を読ませ、決まった形（要約・よくできているところ・所見）で返させる。製品のリポジトリには何も書かない。ジョブ用の DB も作らない
4. **dispatcher が記録して公開する**（`orchestrator/dispatcher/design.py`）。`design.reviewed`（週に 1 回）と artifacts の `DesignReview` に残し、固定 Issue の本文を書き換え、週ごとのコメントを足す。本文の末尾に、所見・直近の数値の診断（`quality.snapshot`）・スコアの推移を埋める（`<!-- factory-design:v1 … -->`）
5. **ページは本文のスナップショットから描く**（`health/design/render_html.py` と `page.html`。LLM を使わない）。週 1 回のクラウドの予約が描き直して同じ URL に公開し、建設日報からリンクする
6. **所見は人が読むためのもの**。ワーカー（実装役・検査役）のプロンプトにも learn（ADR 0013）の入力にも入れない。数値と同じく、目標にすると曲がるため
7. **所見から改善チケットを自動で起票しない**。起票は内部品質の方針 B1（ラインの 15% 上限）の仕組みができてから、人の採否を通す

## 選ばなかった案

- **数値の診断（ADR 0019）に観点を足す**: 境界や用語のずれは静的な数え方では拾えない。LLM を入れると同じ版に同じ数値が返らなくなり、推移が比べられない。数値と読み込みは分ける
- **検査役が PR ごとに見る**: PR の差分からは全体の作り（依存の輪、1 か所への集中）が見えない。週 1 回、main 全体を読む
- **建設者が手で続ける**: 建設者は商用では常駐しない。工場の工程にする
- **製品の CI で動かす**: エージェントの認証と予算の管理が工場の側にある。ジョブとして回せば、予算・停止・記録がほかの工程と同じ仕組みに乗る

## 残り

- 抜き取りの画面（ADR 0019 の残り）と並べ、所見への人の採否（採る・違う）を残す。採否がたまったら、観点の見直しの材料にする
- 改善チケットの起票（B1）。重い所見から、人の採否を通して
- 所見の安定性: 同じ版を 2 回読ませたときの所見の重なりを測り、題のぶれを抑える
