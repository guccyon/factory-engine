# ADR 0016: 工場の PR を続きから仕上げる（途中終了の続き・衝突の解消）

- 状態: 提案（工場のプロセスの変更なのでオーナーの承認を得てからマージする）
- 関係: ADR 0004（supervisor）、ADR 0014（検査役の承認でマージ）、ADR 0015（PR の見張り。衝突は停止 ci: として開く）、`orchestrator/worker/entrypoint.sh`、ケイパビリティ台帳 A9・A11

## 文脈

ワーカーは毎回、既定ブランチから新しいブランチと PR を作る。これで 2 つの止まり方が起きた。

- **途中終了の作り直し**: ターン上限で打ち切られたジョブ（2026-10-30 のジョブ 260、rally #243）を `factoryctl rerun` すると最初から作り直す。ドラフト PR #246 の約 4,400 行は使われず、同じだけのターンと費用をもう一度払った（ジョブ 261、$8.7）
- **工場の PR どうしの衝突**: 同時に流す本数を 2 にしたら、工場の PR が `CHANGELOG.md` の `[Unreleased]` の同じ位置に 1 行ずつ足して衝突した（10-31 の rally #254、#256）。工場は衝突を直せないので、PR は CI が緑のまま止まり、会話のスレッドが手で直した

どちらも「既存の工場の PR のブランチで、既定ブランチを取り込んでから続ける」ができれば工場の中で済む。

## 決定

1. **続きのジョブ**: implement のジョブに「続ける先」（工場のブランチ名・PR 番号・理由 incomplete | conflict）を持たせる。続ける先は `job.enqueued` の payload に置き、dispatcher が形（`factory/issue-<Issue 番号>-job-<n>` と数字の PR 番号）を確かめてからワーカーに環境変数で渡す。ワーカーも同じ形を確かめる
2. **ワーカー**: 続ける先があれば、新しいブランチと PR を作らず、そのブランチを取り出して既定ブランチをマージコミットで取り込む（履歴は書き換えない。force push しない）。衝突したら印を残したままエージェントに渡し、両方の意図を残して解かせる（CHANGELOG の追記どうしは両方残す）。印が残っていたら push せず失敗にする。push したら PR の本文に「## 続きのジョブ」または「## 既定ブランチの取り込みと衝突の解消」の節を足す。途中終了の続きが仕上がったら、未完了の印を外し `Refs` を `Closes` に直してドラフトを外す
3. **途中終了の続き**: `factoryctl rerun <job> --continue` で、前のジョブのドラフト PR のブランチから続ける。`--continue` のない rerun は今までどおり最初から作り直す
4. **衝突の解消**: supervisor は、工場の PR（工場のブランチで、同じリポジトリのもの）が `mergeable_state=dirty` になったら、head ごとに 1 回だけ衝突の解消のジョブを積む（`supervisor.conflict_fix_enqueued`）。解けずに head が変わらなければ二度は積まず、番人のマージ待ちの停止に任せる。`SUPERVISOR_CONFLICT_FIX=0` で止める
5. 新しい head は CI → 検査 → 判定 → 検査役の承認（ADR 0014）をもう一度通る

## 選ばなかった案

- **CHANGELOG を断片ファイル（changelog.d/）にする**: CHANGELOG の衝突はなくなるが、ほかのファイル（生成した型、ADR の表、README の表）の衝突は残る。製品の規約とリリースの組み立ても変わる。衝突の解消を一般に持つ方が広く効く
- **GitHub の update-branch API で取り込む**: 衝突があると失敗するので、肝心の場合に効かない
- **同時に流す本数を 1 に戻す**: 衝突はなくなるが、流れる量が半分になる

## 結果

- 途中終了の rerun が前の作業を使い、ターンと費用の二重払いがなくなる（台帳 A9）
- 工場の PR どうしの衝突が工場の中で解け、同時に 2 本以上流せる（台帳 A11）
- 外部入力の経路: ワーカーのプロンプトに新しく入るのは、制御プレーンが確かめたブランチ名・PR 番号と、git が出した衝突のファイル名だけ。PR の本文は読み戻して節を足すだけで、プロンプトには入れない
- ワーカーのイメージ（base・rust・flutter）の entrypoint.sh を差し替える必要がある。Mac では既存のイメージに entrypoint.sh を重ねて作り直す
