# ADR 0062: S1 の差し止めは、直しが本番に出たのを QA 役が確かめて自分で解く

- 状態: 提案（2026-11-16 オーナーが方針を決めた：「QA が直ったことを確かめたら QA 自身が責任を持って自動解除してください」。この ADR はマージ前にオーナーに見せる）
- 関係: ADR 0043 の O5（S1 の差し止め。解除は人だけ、をこの ADR で改める）、ADR 0053（メジャー不具合の即時修正と再リリース）、ADR 0028 の決定 2（QA 役）、ADR 0049（出荷の QA の関門）

## 文脈

S1 の Incident が開くと、QA 役がラインを差し止める（ADR 0043 の O5）。差し止めの間は S1 の直し（p0）と QA の確かめ直しだけが流れ、ほかのチケットは止まる。
直しは ADR 0053 で人を待たずに本番まで出る（S1 の緊急便は、staging に出たあと supervisor が本番を承認する）。
ところが解除だけは人の手で行う決まりなので、直しが本番に出たあとも、人が気づくまでライン全体が止まったままになる。

2026-11-16 の rally で、これが続けて 2 回起きた。

- 17:20 JST に S1 の rally#1785 で差し止めた。直しは 21:07 に本番に出た。解除は 21:18 で、人の言葉を待った
- 21:34 に S1 の rally#1798 で差し止めた。直しは 21:53 にマージされ、0.54.0 が 21:55 に staging に出た。解除は人を待っている

夜中に S1 が出ると、ラインは朝まで止まる。オーナーは「QA が直ったことを確かめたら、QA 自身が責任を持って自動解除する」と決めた（2026-11-16）。

## 決定

### 1. 解く条件

差し止めに入っている Incident（演習でないもの）の 1 件ずつについて、次の 3 つがそろったら、その Incident は「直った」とする。

| 順 | 条件 | 見るもの |
|---|---|---|
| 1 | Defect の Issue が閉じ、ADR 0053 の緊急便に載った | `major.rereleased`（Incident ごとに 1 件） |
| 2 | その緊急便の版が、本番を立てる製品では本番に、そうでない製品では staging に出ている（その版か、その後の版） | `ship.status` の環境の版と、`release.created` の順 |
| 3 | QA 役が staging で Defect の再現の手順をたどり直し、直ったと答えた（確信度 0.7 以上） | 確かめ直しのジョブ（mode: recheck）の結果 |

差し止めの全部の Incident が「直った」になったら、QA 役が差し止めを解く。1 件でも残っていれば解かない。

### 2. 確かめ直し（mode: recheck）

- 条件 1 と 2 がそろった Incident ごとに、supervisor が QA のジョブを 1 つ積む（固定 Issue `factory:qa`、優先度 p0。差し止めの間も流れる）
- 入力は Defect の Issue（番号・題・本文の再現・期待・実際）。QA 役は staging でその手順を利用者の操作でたどり、`out/recheck.yaml` に Issue ごとの答え（`fixed: yes | no | unconfirmed`、試したこと、見えたもの、確信度）を書く
- 確かめるのは staging。本番に入って利用者のデータを作らない（staging には本番と同じ版か、その後の版が出ている）
- `unconfirmed`（ログインできない等で確かめられなかった）は 1 回だけ積み直す（ADR 0049 の関門と同じ `attempts: 2`）

### 3. 解いたとき・解けないとき

- 直った: QA 役が Incident を閉じ（`incident.closed`、by: qa）、差し止めを解く（`line.hold_released` の by: qa、via: qa_verified、確かめ直しのジョブと答えを添える）。Defect の Issue に確かめた結果を書き、工場の状況の Issue（停止の通知と同じ口）に知らせる。差し止めの停止は閉じるので、受信トレイの対応待ちからも消える
- 直っていない（`no`）: 解かない。Defect の Issue に「直っていなかった」と見えたものを書き、工場の状況の Issue に知らせる。差し止めの停止は受信トレイの対応待ちに残る。次の手（Issue を開き直して直し直すか）は今までどおり工場の着手判定か人が決める
- 確かめられない（積み直しても `unconfirmed`）: 解かない。工場の状況の Issue に「人が確かめて解除してください」と知らせる

### 4. 変えないもの

- 人はいつでも解除できる（操業コンソールの「差し止めを解除」、`factoryctl line release --reason`）
- `factoryctl line release --by qa` のように、名前だけで QA 役を名乗る解除は今までどおり断る。QA 役が解くのは決定 1 の条件を満たしたときだけ
- 演習（drill）の差し止めは自動で解かない（`factoryctl incident drill-end` と人の解除で終える）
- 差し止めの間に流すもの（S1 の直し・QA の確かめ直し・p0）は変えない

### 5. 止める口

supervisor の環境変数 `HOLD_AUTO_LIFT`（既定 1）。0 にすると、確かめ直しを積まず、解除は人だけに戻る。

## 結果

- 夜中の S1 でも、直しが本番に出て QA が確かめれば、ラインは人を待たずに流れ出す
- 解除の記録に「誰が・何を確かめて」が残る（人の解除は理由、QA の解除は確かめ直しのジョブと答え）
- 確かめ直しのジョブの分だけ費用がかかる（S1 1 件につき QA のジョブ 1〜2 本）

## 仮決め

- 確信度の下限 0.7 は、関門の探索の既定と同じ値にした。実績を見て直す
- 直っていなかったときに Issue を自動で開き直して直し直す流れは入れない。まずお知らせで人に見せ、件数を見て決める
