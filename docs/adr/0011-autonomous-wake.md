# ADR 0011: 工場が止まったときに builder を自分で起こす（D8）

- 状態: 承認（2026-10-29 戦略会議 D8。細部は builder に委任、事後報告）
- 関係: ADR 0005（停止と番人）、ADR 0009（操業コンソール）

## 文脈

builder（手元の Claude）は、工場の PR の結果を背景の待ちで見ていた。待ちはセッションの区切りで切れるので、途中終了や CI の失敗に気づかないまま、ラインが何時間も止まることが続いた（2026-10-28〜29 に 3 回、計 約 17 時間。オーナーの「止まってる？」で気づいた）。

## 決定

1. **起こす役は工場の側に置く**。builder のセッションやコーディネーターは作り直されることがあり、そちらに置いた購読や予約は途中で消える。工場（または端末の定期の見回り）が停止を見つけて builder を起こす
2. **見回りは定期の起動で行う**（仮置き 60 分ごと）。開いている停止（idle 以外）、工場の PR の CI の失敗・ドラフト（途中終了）・人へ回した判断・差し戻しの提案を確かめ、当たれば builder に知らせる。読むだけで、工場には何も書かない
3. **起こされた側は冪等にする**。すでに動いていれば何もせずに終わる
4. **停止を閉じるときに、builder を起こしたもの（`woken_by`: pr_event / watcher / schedule / human）を残す**。`factoryctl report stoppages` に人が起こした割合を出し、健康レポートで自律の度合いとして見る
5. **CI が落ちた工場の PR は停止として開く**（factory-engine #54）。検査と judge は CI が通るまで積まないので、黙って止まらないように
6. **番人の通知先は設定で差し替えられる**（`STATUS_NUMBER`: Issue でも PR でもよい）
7. **ホストのスリープを防ぐ**: `orchestrator/scripts/keep-awake.sh` を launchd の LaunchAgent で常駐させ、工場（Compose の project `factory`）のコンテナが動いている間だけ `caffeinate` でスリープを止める。工場が止まれば普段どおり眠る。システムの設定（pmset）は変えず、`uninstall` で元に戻せる。操業コンソールのトグルで止めないこともできる（見張りが 2 分ごとにコンソールへ問い合わせ、居ることの知らせを兼ねる。連絡がないときはトグルを出さない）（2026-10-30 改訂。手で起動する版は紐づけた Docker のプロセスが終わると `caffeinate` も終わり、アイドルスリープで約 11 時間止まった）

## 結果

- 停止に気づくまでの時間が、見回りの間隔（60 分）以下になる見込み。人が起こした割合が下がることを健康レポートで確かめる
- 見回りの起動は端末の定期タスクで、作るにはオーナーの承認が要る
