# ADR 0020: 工場の入れ替えで仕掛かりの作業を壊さない（ラインの一時停止と、ジョブへのつなぎ直し）

- 状態: 提案（工場のプロセスの変更なので、オーナーの承認を得てからマージする）
- 関係: ADR 0003（制御プレーン）、ADR 0005（番人）、ADR 0009（操業コンソール）、ADR 0012（出荷）、ADR 0016・0017（続きのジョブ、実装役の文脈の引き継ぎ）

## 文脈

工場（factory-engine）の変更は、工場の外（建設者）で作られ、Mac の工場に入れ替えて効く。入れ替えには 2 つの困りごとがあった。

- **dispatcher を上げ直すと、実行中のジョブを捨てる**: ワーカーは dispatcher の子プロセスの `docker run --rm` で動き、出力は dispatcher が受けている。
  上げ直すと、新しい dispatcher は起動時に running のジョブのコンテナを止め、`orphaned_by_restart` で失敗にして最初からやり直す（`recover`）。
  40 分近いジョブの途中で上げ直すと、その分のターンと費用を捨てる。だから入れ替えは「実行中のジョブが終わるのを待つ」しかなく、
  2026-10-31 の PR の見張り（#82）の版の切り替えも、ジョブが終わるまで待った
- **ラインを止めて入れ替える手段がない**: 制御プレーン（postgres・オブジェクトストア）や Mac そのものを入れ替えるときは、ワーカーが使うジョブ用の DB が
  消えるので、実行中のジョブは続けられない。新しく流さないようにして、今のジョブが終わるのを待つ手段がなく、建設者が様子を見て手で上げ直していた

オーナーの方針（2026-10-31）: 工場のアップデートは工場の外で起きるので、外から中に干渉するインターフェースが要る。ラインを graceful に止め、入れ替えた後に再開させる。
ラインの仕掛かりの作業が壊れるのは防ぎたい。

## 決定

1. **ジョブはコンテナとして dispatcher から独立させる**。ワーカーのコンテナは名前（`factory-job-<id>`）と印（ラベル `factory.job=<id>`）を付けて起動し、`--rm` を外す。
   コンテナの名前は起動の前に jobs に書く。dispatcher が落ちても、上げ直しても、コンテナは動き続け、終わった後も出力と終了コードを残す。
   後片付け（`docker rm`）は、結果を制御プレーンに記録し終えた dispatcher が行う
2. **上げ直した dispatcher は、running のジョブのコンテナにつなぎ直す**（`recover`）。コンテナが残っていれば（動いていても、終わっていても）、
   出力を最初から読み直し（`docker logs -f`）、終了コードを待ち（`docker wait`）、その後は今までと同じ記録・ラベル・コメントの処理をする。
   打ち切りの時刻はジョブの開始から数える。コンテナが残っていないときだけ、今までどおり `orphaned_by_restart` で積み直す。
   記録が終わっているのに残ったコンテナ（記録の後、片付けの前に落ちた）は消す
3. **ラインの一時停止（drain）と再開（resume）を、外からの操作として置く**。状態の正本は制御プレーン（events の `factory.drain_requested` / `factory.drain_released`）。
   - 一時停止の間、dispatcher は順番待ちのジョブを取り出さない。割り込み（p0）もしない。ラベルでの投入、supervisor の判定・マージ、順番待ちへの積み込みは続ける（再開したらすぐ流れる）
   - 「入れ替えてよい」は、一時停止中で、実行中のジョブが 0 件で、出荷の依頼（ADR 0012）が処理中でないとき
   - 入口は 3 つで同じ関数を通る: `factoryctl drain [--wait 秒] [--reason ..]`（`--wait` は入れ替えてよくなるまで待ち、なれば終了コード 0）、
     `factoryctl drain status`、`factoryctl resume`（チケットを渡さないとき）。操業コンソールの API `POST /api/factory/drain`・`POST /api/factory/resume` と、
     画面上のトグル。`GET /api/state` に状態を出す
   - 一時停止は上げ直しをまたいで残る（上げ直した dispatcher も取り出さない）。再開は明示の操作だけで、自動では解かない
4. **再開を忘れても夜を越さない**: 番人が、一時停止が `WATCH_DRAIN_MIN` 分（既定 30、仮置き）続くと停止 `drain:` を開く（分類 human、待っているもの「入れ替えと再開」）。
   再開すると閉じる。一時停止の間は、ラインが空（idle）の停止は開かない（理由が分かっているので二重に知らせない）
5. **入れ替え方は 2 通りに分ける**（README に手順）
   - **工場のコードだけの入れ替え**（dispatcher・supervisor・console・shipper の版、ワーカーのイメージの作り直し）: 一時停止は要らない。そのまま上げ直す。
     実行中のジョブはコンテナで続き、新しい dispatcher がつなぎ直す。作り直したワーカーのイメージは次のジョブから使われる（実行中のジョブは前のイメージのまま終わる）。
     ただし出荷の処理中は shipper を上げ直さない（`drain status` で見る）
   - **制御プレーンや Mac ごとの入れ替え**（postgres・オブジェクトストア・ネットワーク・Docker・OS の再起動）: `factoryctl drain --wait` で入れ替えてよくなるのを待ち、
     入れ替え、`factoryctl resume` で再開する

## 選ばなかった案

- **入れ替えのたびに drain して待つ**: 実装のジョブは最長 40 分で、入れ替えのたびにラインが空く。コードの入れ替えはつなぎ直しで足りる
- **実行中のジョブを止めて、続きのジョブ（ADR 0016・0017）で再開する**: 止めた時点の作業はブランチに push されておらず、文脈の保存（`handoff.saved`）も PR を作った後にしか起きない。
  つなぎ直しなら何も捨てない。止めて続きから再開する一時停止（すぐ止めたいとき）は、引き継ぎのボリュームが途中の保存に対応してから考える
- **dispatcher の状態をファイルに書いて引き継ぐ**: ジョブの状態の正本はすでに jobs にあり、出力と終了コードは Docker がコンテナに残している。新しい置き場は要らない
- **一時停止を時間で自動的に解く**: 入れ替えに失敗したまま流し始めると、壊れた工場でジョブを回す。解くのは人か建設者の明示の操作にし、忘れは番人が知らせる

## 結果

- dispatcher の上げ直しで実行中のジョブを捨てなくなり、工場のコードの入れ替えでジョブの終わりを待たなくてよい
- 終わったワーカーのコンテナは、dispatcher が記録を終えるまで残る（ディスクの使い方は、記録の数秒〜数分ぶん増えるだけ）
- この版に入れ替える最初の 1 回は、前の版の `--rm` で動いているジョブにもつなぎ直す（動いている間の出力は読める。終わる前に dispatcher が上がっていれば終了コードも取れる）。
  取れなければ今までどおり積み直す
- 記録の途中（コンテナが終わってから jobs の状態を書くまでの数秒）に落ちると、上げ直した dispatcher が同じ結果をもう一度記録する。ラベルとコメントが二重になりうる
- 環境変数: `WATCH_DRAIN_MIN`。イベント: `factory.drain_requested`、`factory.drain_released`、`job.reattached`
