# ADR 0005: 操業停止（Stoppage）の記録と番人

- 状態: 承認（2026-10-27 戦略会議 第 1 回の決定 D3。閾値は委任の範囲で仮置きし、運用で調整する）
- 関係: 戦略会議の議事録（建設者の手元の 50_build-work/strategy/minutes/2026-10-27_strategy-meeting.md の 8 節・12 節）、ADR 0003（制御プレーン）、ADR 0004（supervisor。heartbeat を出す側）

## 文脈

Gen1 の主目的は、デモアプリを作りながら、工場が自律運営するために備えるべき機能を見極めることにある。
P1 入口までに止まった・遅れた事例は 16 件あった（権限 4、実行環境 2、工場の不具合 5、チケット 2、人の判断待ち 2、外部 1）。
どれも人が気づいて手で書いた記録で、気づくまでの時間は測れていない。夜間や不在のあいだにラインが空になっても、誰にも知らされない。
止まった理由を溜めて次から止まらない仕組みに変えるには、停止を工場自身が検知し、型のある記録として残す必要がある。

## 決定

1. **Stoppage を成果物の型にし、制御プレーンの `events` に記録する**。`stoppage.opened` と `stoppage.closed` を `payload.key` で対にし、表は作らず view `stoppages` で読む。状態は events にだけあるので、記録の正本は 1 つ
2. **属性**は 開始・終了・何が止まったか・何を待ったか・分類・検知者・原因・その場の手当て・再発を防ぐ仕組み。分類は `env` / `perm` / `human` / `factory-bug` / `ticket` / `external` に `budget`（契約の使用量上限・予算・時間・ターンの超過）を加えた 7 つ。2026-10-28 に `idle`（ラインが空。積まれたチケットがない）を `human` から分けて 8 つ（オーナー の確認）。検知者は `watcher` / `supervisor` / `builder`
3. **番人は dispatcher の中に置く**（60 秒ごと、トークンを使わない）。開く条件:
   - 実行中 0 かつ投入可能 0 が 20 分（ラインが空）
   - supervisor の heartbeat が 30 分ない（heartbeat が 1 度でも来てから有効にする。ADR 0004 の前でも番人を動かせる）
   - 予算・時間の超過（使用量上限、時間切れ、ターン上限の途中終了）と、人の手当てを待つ失敗（要求が確定しない、未分類の失敗）
   - 打ち切りの時刻を過ぎても running のままのジョブ
   閉じる条件は、ジョブが積まれた・heartbeat が戻った・同じ Issue の次のジョブが始まった・ジョブが終わった。番人が見始める前の失敗は遡って開かない
4. **通知は 1 経路で、差し替え可能にする**。Gen1 は GitHub の工場状況 Issue（`factory:status`、factory-engine）に開始と終了をコメントし、本文を開いている停止の一覧に書き換える。`NOTIFIER` で差し替える（いまは `github-issue` と `log`）。Slack などは足すときにこの関数の裏に置く
5. **番人に見えない停止は builder が手で記録する**（`factoryctl stoppage open / close`）。builder の端末の許可待ちや契約の上限など、制御プレーンの外で起きるものが対象
6. **`stoppages.md` は週次レポートの生成物にする**（`factoryctl report stoppages --from --to`。既定は直近 7 日）。手で書く一覧はやめ、振り返り（何を仕組みに変えるか）だけを人が書く
7. **記録や通知に失敗してもラインは止めない**。番人の例外はログに出して次の周期で続ける

## 選ばなかった案

- **Stoppage の専用の表を作る**: 開いて閉じるだけの状態なら events の対で足りる。正本が 2 つになると、来歴（ADR 0007）の集計とずれる
- **番人を supervisor の中に置く**: supervisor が落ちたことを supervisor 自身は知らせられない。heartbeat の途絶えを見るのは別のプロセスが要る。dispatcher はキューの状態を持っているので、トークンを使わない番人を置くのに向いている
- **通知を最初から複数経路にする**: Gen1 で読むのは建設者 1 人で、GitHub の通知で足りる。経路を増やすより、差し替えられる形にしておく
- **番人が止まった原因まで推定する（LLM で分類する）**: 判断は judge に寄せる（ADR 0006）。番人は条件の一致だけを見て、未分類は `factory-bug` として人が直す

## 結果

- 夜間や不在のあいだにラインが空になったこと、supervisor が落ちたことが、工場状況 Issue の通知で分かる
- 稼働率と停止の内訳を週次レポートで events から集計できる。閾値（20 分・30 分）はここで実測と並べて見直す
- 過去の 16 件（S01〜S16）は `--quiet` で取り込み、同じレポートで読めるようにする
- ラインが空の停止（`idle:`）は、仕事がないこと自体も停止として数える。人がチケットを積むのを待っているのか、承認待ちなのかは `waiting_for` で分ける。数が多すぎてノイズになれば、条件を見直す
