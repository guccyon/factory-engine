# ADR 0021: ラインの後片付け（小さく、機械だけ、ラインとは非同期）

- 状態: 承認（2026-10-31 オーナー）
- 関係: ADR 0013（Learn ループ）、ADR 0017（実装役の引き継ぎのボリューム）、ケイパビリティ台帳 A13・C8

## 文脈

ADR 0017 で、実装役の作業の文脈（報告、仮決め、合図、差分、エージェントの会話の記録）がチケットごとのボリュームに残るようになった。
ADR 0017 のままだと、PR がマージか閉じられてから 7 日でボリュームを消すだけなので、Learn ループ（ADR 0013）と工場の健康指標の材料が失われる。

2026-10-31 オーナーの方針:

- 最初は小さく機械的な後片付けだけでよい
- セッションの生データをそのまま渡すと学習側の精査が大変なので、残すにしても一定のクレンジングは要る。ただし、Learn ループの設計が固まり、
  学習の入力に何が要るかが分かった時点で、片付けの流れを見直す。健康指標の可視化側からの要求も加味する
- 片付けはラインの完了をきっかけにするが、ラインの作業とは非同期に扱い、成果物には含めない。出荷するかは最終的に人が判断し、
  出荷しないと判断したときの手戻りを小さく保つため、ラインのオーバーヘッドを増やさない
- 後片付けと実装の再開（ADR 0017）は別の文脈として扱う

## 決定

1. **ラインの外で動く**: 後片付けは dispatcher の別の糸（`tidy_loop`、既定 5 分ごと）で動く。ジョブとして積まず、ジョブの枠も使わない。
   PR にも Issue にも何も足さない
2. **きっかけ**: 工場の PR がマージか閉じられ（`pr.merged` / `pr.closed_unmerged`）、そのチケットの引き継ぎのボリュームが残っていて、
   同じチケットのジョブが待ち・実行中でないこと
3. **永続化**: ボリュームの中身を、選り分けずにそのまま tar.gz でオブジェクトストアの `tickets/<repo>/<issue>/handoff-<日時>.tar.gz` に置く
   （`handoff.archived`）。エージェントの会話の記録（`agent/`）も含める。後で要る入力が分かってから選り分けられるよう、今は落とさない
4. **破棄**: 置けたらボリュームを消す（`handoff.removed`、why=tidy）。置けなければ消さずに次の回でやり直す。置けたが消せなかったときは、
   次の回で置き直さずに消すだけにする。置けないまま日がたったものは、ADR 0017 の期限の片付け（`HANDOFF_KEEP_DAYS`）が受け皿になる
5. **LLM は使わない**。クレンジング、申し送り、保留した判断の再起票は、この ADR の見直しで決める
6. **止め方**: `TIDY_ENABLED=0`（期限の片付けだけ残る）。`HANDOFF_VOLUMES=0` ならボリュームごと作らないので後片付けも動かない

## 選ばなかった案

- **後片付けをラインの最後のジョブにする**（指示役が積み、エージェントが申し送りと再起票の案を出す）: ラインの完走が延び、
  出荷しない判断のときの手戻りが大きくなる。案の質を測る土台もまだない（2026-10-31 に一度作り、オーナーの方針で取り下げた）
- **期限で消すだけ（ADR 0017 のまま）**: Learn ループと健康指標の材料が失われる
- **今からクレンジングして残す**: 何を残すべきかは、学習と健康指標の入力が決まってからでないと決められない

## 結果

- ラインの完走時間と成果物は変わらない
- チケットの文脈がオブジェクトストアに残り、Learn ループ（P3）と健康指標（台帳 C8）の入力の候補になる。どこに何があるかは
  `handoff.archived`（`blob_key`・`bytes`・`outcome`）で引ける
- 会話の記録を含むので大きくなり得る。保持期間と選り分けは見直しのときに決める
- マージの直後にボリュームが消えるので、その後に同じチケットで続きのジョブが動くと、ボリュームなしで始まる（ADR 0017 の想定どおり、
  PR のブランチと本文だけで続ける。ボリュームができ直したら、それも次の回で片付ける）

## Learn ループと健康指標との関係

2026-10-31 オーナー: Learn ループ（P3）と工場の健康指標の可視化のアーキテクチャを検討するときは、後片付けを情報取得の口として
うまく活用できる構造を視野に入れる。ラインのワーカーに情報収集の仕事を足すとラインの完走が延びるので、学習と健康指標が使う
記録（選り分け・クレンジング済み）は、ラインの外で非同期に動く後片付けが作る形を第一候補にする。

## 見直しのきっかけ

- P3 で学習の入力データの形が決まったとき
- 健康指標で使うセッションログの項目が決まったとき
- オブジェクトストアの容量が気になり始めたとき
